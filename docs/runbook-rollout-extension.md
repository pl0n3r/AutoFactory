# Runbook de rollout y rollback reversible — AutoFactory #262

**Estado:** preparación documental en fase `construccion`. **NO_GO / no publicar ni activar nuevas versiones** por la existencia de este runbook. AutoFactory es una extensión local Chrome/Safari, **no** un servicio web ni un hosting. Fuente de autoridad: `decisiones.yml` D-056, D-060, D-061 y D-062; `AGENTES.md`; [#122](https://github.com/pl0n3r/AutoFactory/issues/122) smoke Safari real aún bloqueado; [#258](https://github.com/pl0n3r/AutoFactory/issues/258) checklist; [#262](https://github.com/pl0n3r/AutoFactory/issues/262).

## 1. Preparación y corte exacto sin publicación

1. Obtener `main` y commit SHA exacto; proponer `vX.Y.Z` solo si existe decisión/corte autorizados. Congelar inputs y rechazar un `main` que cambió entre preflight y publish. La versión de `manifest.json`, `safari/ChatGPT Autopilot Local Extension/Resources/manifest.json`, `package.json`, `package-lock.json` y raíz `packages[""]` del lock ha de coincidir. Ejecución offline reproducible: `node scripts/verify-release-metadata.cjs vX.Y.Z` solo en un corte permitido. **Este PR no crea ni mueve tags**.
2. Calcular procedencia y digests SHA-256 de los assets de Chrome y Safari con `scripts/release-artifact-attestation.cjs` y `scripts/verify-release-evidence.cjs`. Contrastar artefacto reconstruido, tag y SHA con evidencia firmada de canal. Copiar recibos **sin secretos ni contenido de conversaciones** a un registro privado autorizado. Nunca elevar un recibo sintético, un build unsigned o un GitHub Release existente a certificación de instalación.
3. `.github/workflows/release.yml` contiene preflight exact-main, `chrome_smoke`, `safari_smoke` y publish dependiente de ambos, pero **el paso Safari actual es `Real unsigned Safari/Xcode build smoke`**: construye con `CODE_SIGNING_ALLOWED=NO`; no acredita Safari firmado, notarizado, instalado, habilitado ni smoke **real de uso**. [#122](https://github.com/pl0n3r/AutoFactory/issues/122) conserva esa deuda. `scripts/verify-release-evidence.cjs` requiere `preflight=success`, `publish=success`, `chrome_smoke=success`, `safari_smoke=success`, `rollback=success` para el **mismo** tag/SHA, pero la semántica de esas señales requiere prueba genuina independiente.
4. Antes de publicar, verificar cuenta/titularidad y **firma/distribución Chrome/Safari** de los canales aprobados. Chrome: paquete MV3 y control de tienda/instalación autorizado. Safari: app nativa contenedora, firma y notarización/aprobación según el canal, instalación y habilitación de la extensión en Safari. La cuenta Apple/Chrome, certificados, aprobación de gastos o cambios de canal son `DEL_DUEÑO`; ninguna automatización los inventa, compra o solicita a un servicio.

## 2. Puertas de corte (todas fail-closed)

| ID | Área | Evidencia y acción exigida | Tipo | Rechazo |
| --- | --- | --- | --- | --- |
| G-01 | Corte | Tag vX.Y.Z y commit SHA de 40 hex; comprobar tag=HEAD exacto de main sin drift | OBLIGATORIO | No crear tag ni publicar desde una rama o SHA distintos |
| G-02 | Paridad | Versiones iguales en manifest Chrome, Safari Resources, package.json, package-lock.json y root lock | OBLIGATORIO | Rechazar mismatch o archivo faltante |
| G-03 | Procedencia | Atestación reproducible de todos los assets Chrome/Safari, digests SHA-256 por paquete y origen de artefacto | OBLIGATORIO | Asset modificado, ausente o checksum desconocido => NO_GO |
| G-04 | Firma | Verificar firma/identidad y certificados del canal Chrome autorizado y bundle Safari firmado/notarizado cuando aplique | DEL_DUEÑO | Build Safari unsigned NO acredita firma, canal ni aprobación |
| G-05 | Canal | Validar aprobaciones Chrome Web Store o distribución aprobada, y Safari extensión embebida en aplicación autorizada | DEL_DUEÑO | No distribuir ZIP ad hoc ni saltar tiendas/permisos |
| G-06 | Chrome real | Instalación/actualización Chrome MV3 sobre extensión cargada, popup y flujo local seguro, versión y SHA | OBLIGATORIO | npm test solo no acredita actualización real |
| G-07 | Safari real | SMOKE_SAFARI_REAL: instalar, habilitar y cargar extensión Safari firmada desde app autorizada, popup y flujo, versión y SHA | OBLIGATORIO | NO_GO si solo hay build unsigned, Xcode fake, paridad de fuentes o check skipped |
| G-08 | Privacidad | No exponer chats, tokens, cookies, ids de conversación; consentimiento/política antes de cualquier ControlBot real | OBLIGATORIO | D-061 y ControlBot#20 impiden pairing/tráfico real |
| G-09 | Gradual | Cohortes opt-in con pausa y criterios de avance/abort: instalación, errores, degradación, actualización y límites | OBLIGATORIO | No elevar porcentaje sin gates Chrome y Safari reales |
| G-10 | Retención | Guardar tag/commit, digests, instaladores firmados y manifiestos de versión previa instalable sin borrar assets | OBLIGATORIO | No reemplazar release/assets firmados anteriores |
| G-11 | Rollback | Deshabilitar rollout, reinstalar versión previa firmada por canal oficial y verificar apertura/carga/version/SHA | OBLIGATORIO | Sin borrar datos locales ni sobrescribir storage real |
| G-12 | Post-rollback | Repetir smoke Chrome y Safari real tras rollback, verificar salud local y diagnóstico minimizado | OBLIGATORIO | Resultado UNKNOWN/errores/ausencia de Safari real => NO_GO |

**Criterio binario de admisión:** `NO_GO` salvo que **todos los gates `OBLIGATORIO` tengan recibos autenticados, completos, terminales, ligados al mismo tag/SHA y de ambiente real donde aplica**, y además las autorizaciones `DEL_DUEÑO` estén aprobadas. `SMOKE_SAFARI_REAL` es duro: `safari_unsigned_build=success` jamás lo satisface. `UNKNOWN`, `skipped`, `in_progress`, `failure`, enlaces rotos o mismatch de SHA => `NO_GO`. Ningún check de CI aprueba por sí solo instalación, actualización o distribución.

## 3. Distribución y rollout progresivo

- **Canales admitidos:** GitHub Releases mediante pipeline oficial para artefactos de referencia con checksum; instalación Chrome mediante Chrome Web Store o canal corporativo aprobado; Safari mediante contenedor nativo firmado/aprobado en macOS y Safari habilitado. Ningún ZIP manual ni reemplazo de paquete previamente publicado. Canales, firma, identidad y costos se deciden con autorización documentada, no desde este PR.
- **Fase 0 (preparación):** verificar G-01..G-12, respaldo no destructivo de preferencias locales permitido por autorización y versión anterior instalable intacta. Garantizar paridad de fuentes y smoke independiente Chrome/Safari.
- **Fase 1 (canario opt-in):** solo tras autorizaciones explícitas y `GO` autenticado, instalar/actualizar en entorno consentido; comparar tag/SHA del paquete instalado, apertura y popup, errores, presupuesto/limites locales y estabilidad. No leer chats ni capturar tokens. Ante degradación o falta de evidencia **PAUSAR**.
- **Fase 2 (aumento):** ampliar progresivamente solo si Chrome/Safari real permanecen verdes y el responsable del rollout autoriza la siguiente cohorte. Umbrales, población y tiempos deben ser definidos y aprobados; no inventar porcentajes. Cancelar en error, fuga de datos, drift de firma, ausencia de smoke, cambios inesperados de permisos o fallo de instalación.
- **Post-actualización:** guardar matriz `tag | SHA | digest Chrome | digest Safari | firma | canal | smoke Chrome | SMOKE_SAFARI_REAL | cohortes | incidente/rollback`, sin identificadores de cuenta o chat. Conservar versión anterior y recibos.

## 4. Rollback reversible y post-rollback

1. **Abortar y aislar:** detener nuevas instalaciones/cohortes y deshabilitar únicamente el rollout del canal afectado. No desactivar seguridad, no elevar permisos, no borrar versiones y no borrar assets existentes. El kill switch local/puente ControlBot no autoriza tráfico remoto: D-061 permanece vigente.
2. **Elegir versión anterior:** recuperar **artefacto anterior instalable** previamente conservado, mismo tag, digest SHA-256 y firma/distribución de canal aprobado; confirmar compatibilidad y la posibilidad de reinstalar sin modificar el estado real de la extensión. Si la plataforma no permite downgrade no destructivo, **NO_GO**, conservar instalación actual aislada y documentar incidente, sin forzar sobrescritura.
3. **Conservar estado local:** no sobrescribir `chrome.storage`, preferencias, datos reales, tabs/chat, tokens ni rutas de conversación; no ejecutar una migración inversa destructiva ni eliminar backups. No exportar ni registrar datos de conversación o secretos. Futuros mecanismos de respaldo/restauración requieren hoja específica [#260](https://github.com/pl0n3r/AutoFactory/issues/260), no quedan acreditados aquí.
4. **Reinstalación autorizada:** restaurar versión anterior usando Chrome Web Store/canal aprobado y contenedor Safari firmado, con consentimiento y procedimientos de cada plataforma. Si implica un cambio de permisos, pedir nueva aprobación; prohibido bypass de controles.
5. **Post-rollback obligatorio:** volver a verificar versión/tag/SHA del paquete instalado, firma, carga/popup Chrome y **SMOKE_SAFARI_REAL** en Safari de verdad, ausencia de errores nuevos y conservación de estado local. Evidencia faltante o `UNKNOWN` deja resultado `NO_GO` y servicio aislado; **no** marcar `GREEN`, `entregado` ni `VALIDATED_IN_PRODUCTION`.
6. **Retención y seguimiento:** conservar instaladores anteriores y sus digests, evidencias del incidente, acciones y resultados. Nunca reemplazar o borrar releases históricas por revertir un despliegue. Si falla el rollback, congelar rollout y escalar por canal de incidentes del titular, sin manipular chats/datos reales.

## 5. Evidencia, negativa y límites del PR

- Un `npm test`, `Validate / Pruebas y smoke Chrome`, test de navegador efímero o build unsigned de Xcode acreditan código/compatibilidad **offline**, **no smoke Safari real**. La firma/distribución y la actualización/rollback genuinos exigen una sesión de Safari instalado con recibos autentificados.
- Prueba estructural local: `python3 -m unittest tests.test_runbook_rollout_extension -v`; se incluye solo un test documental/regresión, sin acceder a navegadores, red o cuentas. Para prueba completa del producto, `npm test` y Validate exact-HEAD según Factory. La aceptación de #262 no activa ningún pipeline Release.
- **Límites:** no publicar `vX.Y.Z`, no crear asset ZIP manual, no activar pairing ni transporte ControlBot, no realizar gastos, no usar PII/secretos, no declarar `GREEN` por build o CI, no crear tareas manuales para el dueño. El procedimiento documenta las puertas para una decisión posterior.
- **Reversión de esta implementación:** revert del squash de #262 retira dos archivos (runbook y prueba) sin modificar la extensión ni la distribución. La reversión de una extensión instalada es otra operación, bajo autorización y smoke real, no un efecto del merge.
